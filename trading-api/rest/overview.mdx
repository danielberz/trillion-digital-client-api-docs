The REST API provides **historical market data**. Everything else — live prices,
RFQ, order entry, execution reports, trades, balances, and transfers — is on the
[WebSocket API](/trading-api/websocket/overview) or
[FIX](/trading-api/fix/overview).

```
https://sandbox.trading.trilliondigital.io/v1     # sandbox
https://trading.trilliondigital.io/v1             # production
```

<Warning>
REST is a **small** part of this API, and assuming otherwise is the most common
way an integration starts down the wrong path. If you are planning to poll
endpoints for orders, trades or balances, read
[WebSocket commands](/trading-api/websocket/commands) first — those operations do
not exist over REST.
</Warning>

## Authentication

Identical to the WebSocket handshake — `ApiKey`, `ApiTimestamp`, and `ApiSign`
headers on every request. The signed string differs only in that query and body
are appended when non-empty:

```
GET\n<ApiTimestamp>\n<host>\n<path>[\nquery][\nbody]
```

See [Authentication](/trading-api/authentication) for working examples.

<Warning>
Every request needs a freshly generated timestamp and signature. There is no
session and no token to cache — a signature is valid only for the moment it was
made.
</Warning>

## Response envelope

Responses use the same envelope as WebSocket streams.

<ResponseField name="type" type="string" required>The entity type in `data`.</ResponseField>
<ResponseField name="ts" type="datetime" required>Server timestamp.</ResponseField>
<ResponseField name="data" type="object[]" required>
  The rows. Always an array, even for a single result.
</ResponseField>

## What is available

See [Endpoints](/trading-api/rest/endpoints) — historical OHLCV bars, and a table
pointing to the WebSocket stream for everything else.

<Note>
Plain request/response access to accounts, settlement and reporting is what the
[Platform API](/platform-api/overview) is being designed to provide. Until it
ships, historical reads run through WebSocket subscriptions with a `StartDate`.
</Note>
